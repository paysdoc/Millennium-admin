# Chore: Find existing worktree based on issue type and issue number only

## Metadata

## Chore Description
When an ADW workflow starts, it currently generates a branch name (via AI agent or recovery state) and then searches for an existing worktree using that exact branch name. The problem is that when a process restarts after a crash (without recovery state), the branch name generated by the AI agent may be subtly different from the one used in the previous run (e.g., different slug), causing the worktree lookup to miss the existing worktree. This leads to duplicate branches for the same issue.

The solution is to add a function that finds existing worktrees using only the reasonably static aspects of an issue — the issue type prefix (e.g., `feature`, `bugfix`, `chore`, `review`) and the issue number — before attempting to generate a new branch name. If a worktree is found, its actual branch name is reused, avoiding duplicates entirely.

### Step 1: Add `findWorktreeForIssue` function to `adws/github/worktreeOperations.ts`

- Add a new exported interface `WorktreeForIssueResult` with two fields:
  - `worktreePath: string` — the absolute path to the worktree
  - `branchName: string` — the branch name checked out in that worktree
- Add a new exported function `findWorktreeForIssue(issueType: IssueClassSlashCommand, issueNumber: number): WorktreeForIssueResult | null`
- Import `IssueClassSlashCommand` and `branchPrefixMap` from `../core`
- Implementation logic:
  1. Get the branch prefix from `branchPrefixMap[issueType]` (e.g., `feature`, `bugfix`, `chore`, `review`)
  2. Run `git worktree list --porcelain` to get all worktrees
  3. Parse the output, tracking the current worktree path and branch for each block
  4. For each worktree in `.worktrees/`, check if the directory name matches the pattern `{prefix}-issue-{issueNumber}-` using a regex: `new RegExp('^' + prefix + '-issue-' + issueNumber + '-')`
  5. If a match is found, return `{ worktreePath, branchName }` where `branchName` is extracted from the `branch refs/heads/...` line
  6. If no match is found, return `null`
  7. Wrap in try/catch, returning `null` on error
- Add a `log` call when a worktree is found to provide observability

### Step 2: Export the new function from `adws/github/index.ts`

- Add `findWorktreeForIssue` and `type WorktreeForIssueResult` to the `// Worktree Operations` export block in `adws/github/index.ts`

### Step 3: Update `initializeWorkflow` in `adws/phases/workflowLifecycle.ts`

- Import `findWorktreeForIssue` from `../github` (add it to the existing import statement)
- In the `else` branch (when no `options?.cwd` is provided), restructure the worktree lookup logic:
  - **Before generating a branch name**, call `findWorktreeForIssue(issueType, issueNumber)` to check if a worktree already exists for this issue type and number
  - If `findWorktreeForIssue` returns a result:
    - Set `branchName` to the result's `branchName`
    - Set `worktreePath` to the result's `worktreePath`
    - Call `mergeLatestFromDefaultBranch(defaultBranch, worktreePath)` and `copyEnvToWorktree(worktreePath)`
    - Log that an existing worktree was found by issue pattern
    - Skip branch name generation and worktree creation entirely
  - If `findWorktreeForIssue` returns `null`:
    - Proceed with the existing logic: check recovery state for branch name, or generate one via `runGenerateBranchNameAgent`
    - Then check `getWorktreeForBranch(branchName)` as before
    - If not found, `checkoutDefaultBranch()` and `ensureWorktree(branchName, defaultBranch)`
- This ensures that the issue-based lookup happens first (before any AI branch name generation), and the exact branch name lookup remains as a fallback for when the issue-based lookup doesn't match (e.g., branches with non-standard naming)

## Notes
- IMPORTANT: strictly adhere to the coding guidelines in `/guidelines`. If necessary, refactor existing code to meet the coding guidelines as part of accomplishing the chore.
- The `removeWorktreesForIssue` function in `worktreeCleanup.ts` already uses a similar pattern (`-issue-{issueNumber}-`) to find worktrees by issue number. The new `findWorktreeForIssue` function adds the issue type prefix to the pattern for more precise matching and also returns the branch name.
- The regex pattern must use `-issue-{number}-` (with trailing dash) to prevent partial matches (e.g., issue 1 matching issue-10). This follows the same approach as `removeWorktreesForIssue`.
- The function should only match worktrees in the `.worktrees/` directory to avoid false positives with the main repository.
- The issue-based lookup in `initializeWorkflow` is placed before both recovery state branch name lookup and AI branch name generation, since it's the most reliable way to find an existing worktree regardless of how the branch name was originally generated.
